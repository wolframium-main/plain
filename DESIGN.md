# plain — дизайн

Этот документ — источник истины для всех решений. Новая функция или настройка
появляется в коде только после того, как её обоснование появилось здесь.

## Проблема

Современные браузеры перегружены интерфейсом, пытаются быть умными, а большая
часть их функций бесполезна. При этом настроить можно всё, то есть решения
переложены на пользователя.

## Принципы

1. **Интерфейс не мешает.** На экране только то, без чего нельзя обойтись.
2. **Браузер предсказуемый, а не умный.** Делает ровно то, что сказали: никаких
   подсказок, автодействий, рекомендаций и ИИ.
3. **Функций мало.** Каждая должна доказать, что она необходима.
4. **Настроек мало.** Решения принимаем мы, а не перекладываем на пользователя.
5. **Браузер не подстраивается под привычки, а формирует новые.**
6. **Браузер не опекает пользователя** и не защищает его от самого себя.
7. **Браузер — родное приложение GNOME.** Не подражание, а настоящее: то, что
   может нарисовать или решить GNOME, рисует и решает GNOME.

Приватность — не цель проекта.

## Платформа и технологии

| Решение | Почему |
|---|---|
| Linux, рабочий стол GNOME | На нём работает автор; в другом окружении plain тоже запустится, но выглядеть будет как программа GNOME. |
| Свой браузер на встраиваемом движке, без форков | У нас своё видение; форк — это чужие решения и вечная борьба с апстримом. |
| GTK 4 и libadwaita | Только так приложение выглядит и ведёт себя как родное: тема, акцентный цвет, шрифты, анимации и рамка окна приходят из GNOME. |
| WebKitGTK 6.0 | Встраиваемый движок для GTK, на нём сделан GNOME Web. QtWebEngine в GTK не встроить. |
| Rust (gtk4-rs, libadwaita-rs, webkit6) | Так сейчас пишут новые программы GNOME; безопасная память и меньше шаблонного кода, чем на C. |

**История.** Версия 0.1.0 была на Qt 6 и QtWebEngine (Chromium) и выглядела по
личной дизайн-системе автора. В GNOME она смотрелась чужой, и подражание
GNOME средствами Qt отвергнуто: в 0.2.0 браузер переписан заново. Всё
поведение сохранилось; сменились оболочка и движок.

## Что браузер помнит

| | Решение | Почему |
|---|---|---|
| Назад / вперёд во вкладке | Есть, только в памяти | Без этого навигация невозможна. |
| История посещений | Нет | Функций мало. |
| Восстановление закрытых вкладок | Нет | Функций мало. Закрытая вкладка закрыта навсегда. |
| Закладки | Нет | Функций мало. |
| Куки и логины | Сохраняются | Браузер, где каждый день входишь заново, не простой, а неудобный. |
| Вкладки прошлого запуска | Не восстанавливаются | Следует из отсутствия истории. |

Данные — в `~/.local/share/plain/` (куки, хранилища сайтов, список фильтров),
кэш — в `~/.cache/plain/`.

## Окно и вкладки

- **Одно окно.** Второй запуск `plain адрес` передаёт адрес уже открытому окну
  (это делает GApplication через D-Bus).
- **Не больше 5 вкладок**, число фиксировано. Если вкладок нужно помнить много,
  то их открыто слишком много.
- **Вкладки скрыты.** Список показывает команда `:tabs`.
- **Шестая вкладка:** появляются список и строка с `:close `. После закрытия
  одной вкладки новая открывается сама. Намерение пользователя не теряется.
- **Сайт просит новую вкладку — получает новую вкладку.** Браузер не
  переинтерпретирует ссылки. Такая вкладка тоже подчиняется лимиту. Вкладка
  остаётся связана с открывшей её страницей (`window.opener`), поэтому
  работает вход через Google и GitHub во всплывающем окне.
- **Окна, открытые без действия пользователя** (рекламные попапы), WebKit не
  открывает.

## Интерфейс

На экране только страница. Всё остальное — родные элементы libadwaita,
которые появляются по требованию:

```
┌──────────────── Qt 6 Docs ────────────────┐  ← header bar: прячется
│                 doc.qt.io                  │
├────────────────────────────────────────────┤
│                                            │
│               страница                     │
│                                            │
│          ╭────────────────────────╮        │  ← тост
│          │ Загружено: ~/report.pdf│        │
├────────────────────────────────────────────┤
│   ╭──────────────────────────────────╮     │  ← список вкладок
│   │ 1  Hacker News                   │     │
│   │ 2  Qt 6 Docs                  ✓  │     │
│   ╰──────────────────────────────────╯     │
│   [ :close █                        ]      │  ← командная строка
└────────────────────────────────────────────┘
```

- **Header bar прячется, как в Showtime** (`AdwToolbarView`). Страница уходит
  под него, а он выезжает, когда открыта командная строка, когда указатель у
  верхнего края окна и когда вкладка пустая. В нём заголовок страницы, под
  ним домен (`AdwWindowTitle`), и кнопки окна. Других кнопок нет.
- **Нижняя панель** — нижняя полоса того же `AdwToolbarView`. В ней
  командная строка (`GtkEntry`), список вкладок и подсказки клавиш. Она
  сдвигает страницу, как полоса поиска в программах GNOME. Содержимое
  ограничено шириной 640px и стоит по центру (`AdwClamp`).
- **Список вкладок** — `boxed-list` из `AdwActionRow`: номер, заголовок,
  домен; текущая вкладка отмечена галочкой. Строки не нажимаются: управление
  командами.
- **Сообщения** — тосты (`AdwToast`), 4 секунды.
- **То, что держит страницу**, — баннер (`AdwBanner`) над страницей: вопрос о
  разрешении, недействительный сертификат. Пока баннер виден, страница не
  уходит под header bar, чтобы баннер не перекрывался.
- **Загрузка** — полоса OSD (`GtkProgressBar` со стилем `osd`) по верхнему
  краю страницы, как в GNOME Web.
- **Подсказки клавиш** — клавиши-«кнопки» `GtkShortcutLabel`.
- **Адресная строка скрыта полностью.** Защита от фишинга — не задача
  браузера.
- **Контекстное меню** — родной поповер WebKitGTK, из которого оставлены три
  пункта, в зависимости от того, по чему кликнули: «Копировать», «Копировать
  адрес ссылки», «Сохранить изображение». Если ни один не подходит, меню не
  появляется.
- **Пустая вкладка** показывает фон окна. Под настоящими страницами — белый,
  как ждут сайты без собственного фона.

## Внешний вид

Своих стилей нет вообще: ни цветов, ни шрифтов, ни отступов, кроме сетки
GNOME (6, 12, 24px). Светлая и тёмная тема, акцентный цвет, шрифт, рамка
окна и анимации берутся из GNOME. Если в GNOME выключены анимации, панели
появляются без них.

Тексты — в тоне GNOME: нейтрально, без обращения на «ты», без
восклицательных знаков. Ошибка говорит, что случилось, потом что делать.

**Иконка** — в стиле иконок GNOME: белый лист, на нём синее двоеточие (с
двоеточия начинается любая команда), цвета из палитры GNOME. Есть и
символьная версия. `data/icons/`.

## Управление

Управление только через командную строку: команду нужно осознанно напечатать,
поэтому импульсивных действий нет. Единственная горячая клавиша — **Ctrl+;** —
открывает строку. Это клавиша, на которой находится двоеточие, а с двоеточия
начинается любая команда. Ctrl+L из других браузеров не взята намеренно: браузер
не подстраивается под привычки. Клавиша перехватывается раньше страницы, так
что ни один сайт не может её «съесть».

| Ввод | Действие |
|---|---|
| адрес | открыть в текущей вкладке |
| любой текст с пробелом или без точки | искать в Google |
| `:new [адрес]` | новая вкладка (пустая — сразу со строкой) |
| `:tabs` | список вкладок |
| `:tab N` | перейти на вкладку N |
| `:close [N]` | закрыть текущую или N-ю |
| `:back`, `:forward`, `:reload` | навигация |
| `:find текст` | поиск по странице; повтор — следующее совпадение, `:find` — сброс |
| `:zoom N` | масштаб в процентах, 25–500 |
| `:url` | скопировать адрес страницы |
| `:proceed` | открыть страницу с недействительным сертификатом |
| `:devtools` | веб-инспектор WebKit |
| `:quit` | выйти |

Поиск — только Google, без настройки.

## Остальное

- **Загрузки** сохраняются в папку «Загрузки» без вопросов, файлы не
  перезаписываются (`file (1).txt`). Менеджера загрузок нет.
- **PDF** не показывается внутри: файл сохраняется и открывается программой,
  которую GNOME назначил для PDF.
- **Блокировка рекламы** встроена и не настраивается: EasyList, обновляется раз
  в 4 дня. Правила переводятся в формат фильтров содержимого WebKit (как у
  Safari), WebKit компилирует их один раз и хранит готовыми. Блокируются
  запросы к рекламным доменам; страницу, на которую перешёл сам пользователь,
  браузер не блокирует никогда.
- **Разрешения сайтов.** Камера, микрофон и показ экрана — вопрос в баннере,
  ответ в командной строке: `y` — разрешить, `n` или Esc — запретить. Ответ
  не запоминается. Всё остальное (уведомления, геолокация, буфер обмена,
  захват указателя) запрещено без вопросов: именно это делает браузер
  навязчивым.
- **Недействительный сертификат.** Страница ждёт, а над ней висит баннер:
  «Сертификат example.com недействителен: срок действия истёк. Открыть всё
  равно — :proceed». Открыть можно только осознанно, напечатав команду;
  переход куда-то ещё означает «нет». Баннер привязан к своей вкладке. После
  `:proceed` сертификат принят для этого сайта до перезапуска браузера.
- **Веб-инспектор** — встроенный инспектор WebKit.
- **Полноэкранное видео** работает; панели при этом не появляются.

## Исключения для сайтов

Браузер ведёт себя одинаково на всех сайтах. Исключение появляется, только
если без него нужный сайт не работает, и каждое записывается здесь.

Сейчас исключений нет. Вход в Google, ради которого в 0.1.0 пришлось
представляться Firefox, в WebKitGTK решается встроенными заплатками движка
(site-specific quirks), которые включены по умолчанию; так же работает GNOME
Web. plain представляется сайтам обычным WebKitGTK.

## Убрано

Менеджер паролей (есть KeePassXC и pass), расширения, синхронизация, профили,
приватный режим, встроенный просмотр PDF, режим чтения, переводчик, ИИ, лента на
новой вкладке, поисковые подсказки, боковые панели, скриншоты, VPN, кошельки,
HTTP-авторизация (окно логина и пароля от браузера: страницы, которым она нужна,
просто не открываются), главное меню в header bar.

## Решения, принятые при реализации

Они следуют из принципов, но не обсуждались отдельно. Каждое можно пересмотреть.

- **Esc** или клик по странице закрывают строку. Если в этот момент ждала
  отложенная вкладка, она отменяется.
- Закрытие **последней вкладки** оставляет пустую вкладку с открытой строкой.
  Выход — `:quit` или кнопка закрытия окна.
- Опечатка в команде **не закрывает строку**, чтобы её можно было исправить.
- Клик колёсиком или Ctrl+клик открывают ссылку **в фоне**, и тост сообщает
  номер новой вкладки.
- `:find` сообщает число совпадений («Совпадений: 3»). Номер текущего
  совпадения WebKit не сообщает.
- Блокировщик учитывает только правила для **целых доменов**, остальные
  пропускает: лучше пропустить рекламу, чем сломать сайт.
- На вопрос о разрешении «да» — это `y`, `yes`, `д`, `да` и `н` (клавиша Y в
  русской раскладке). Любой другой ответ, Esc или клик по странице — «нет».
  Несколько запросов подряд задаются по очереди.
- ID приложения — `io.github.wolframium_main.Plain`: по нему GNOME связывает
  окно, ярлык и иконку. Команда в терминале — `plain`.

## Лицензия

**GPL-3.0 или новее.** Код открыт, и любая изменённая версия, которую
кто-то распространяет, тоже обязана быть открытой: никто не выпустит
закрытый «plain с рекламой». GTK, libadwaita и WebKitGTK распространяются под
LGPL и с GPL совместимы.

## Распространение

Пакет для Arch Linux прямо из репозитория на GitHub (`wolframium-main/plain`),
без AUR: `packaging/aur/PKGBUILD` скачивает исходники по тегу релиза и
собирает браузер через cargo. Каталог называется `aur`, потому что этот же
PKGBUILD вместе с `.SRCINFO` можно без изменений отправить в AUR, если
когда-нибудь понадобится. Для разработки достаточно `cargo run`.

Других пакетов (Flatpak, deb) нет. Flatpak — естественный следующий шаг для
приложения GNOME, если plain понадобится кому-то кроме автора.

**Новый релиз:** поднять `version` в `Cargo.toml` и `pkgver` в PKGBUILD,
добавить `<release>` в `data/*.metainfo.xml`, обновить `.SRCINFO`
(`makepkg --printsrcinfo > .SRCINFO`), затем создать на GitHub релиз с тегом
`vX.Y.Z`.
